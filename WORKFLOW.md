# Operating contract

Head → Worker → Validate → Internal Auditor → Head. One authorized mutation lane; all other scheduled tasks read-only. A task prompt, elapsed time, old receipt or role label is not an exclusive lease. Read canonical GitHub state before work; validate issue/version/branch/current head, authorized actor and exclusive lease, fail closed if missing or changed. Never self-transfer or steal ownership. Stop after one bounded repair or blocker; preserve receipts, release only a safely acquired lease. Review, acceptance and release are distinct; separate owner permission for merge, closure, migration, publication or deployment.

Report material changes only to the existing associated conversation; never create a replacement or launch/delegate another agent. If silence is unsupported, suppress unchanged results when possible; otherwise explicitly label limitation. Read-only watchers must not rerun jobs. Distinguish scheduler success, source head, proposed merge, actual merge, installed release, artifacts metadata vs bytes, mechanical simulation vs genuine independent agent trials. Do not treat missing or stale evidence as PASS. Use PASS/FAIL/BLOCKED/NOT RUN/UNVERIFIED. Track actual UTC start/end and local offset, positives, negatives, proof links and next action. Keep task-specific stable IDs; deduplicate on material facts, not timestamps. No automatic activation. No paid or self-hosted runners, no branch protection requirement. No automatic cross-branch writes.

First configure target repository and timezone; bind each task to the existing conversation in ChatGPT, verify settings and only then enable manually. GitHub cron is not a ChatGPT task launcher; no API for moving a live chat task is assumed. Preserve owner-selected model ceiling and tool availability. Stop when agreed release gates are verified.
