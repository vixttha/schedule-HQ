# Private local history reference

The JSON snapshot is an intentionally bounded reference backend (8 MiB) using only approved Python and JSON, not adoption of SQL or a shared production store. The caller must provide a trusted private durable directory, outside the Git worktree. POSIX rejects group/world readable state; Windows host ACLs must be established by the caller. A cooperative local lock rejects concurrent writes, never automatically reclaims abandoned locks, and does not authorize a GitHub mutation. Same-directory temporary file, fsync, atomic replace and POSIX directory fsync preserve old/new snapshots on normal filesystem failure; OS/power-loss guarantees depend on host/filesystem. Windows directory fsync is not asserted. An ambiguous failure requires explicit readback; never blind retry. Private export/import is checksummed for accidental corruption, not cryptographically authenticated; restored claims do not prove present host authority. Restore only to empty private directory. No public upload of private state, no raw live payloads, no automatic retention deletion or migration. No cross-run durable storage on ephemeral runner disks.

Every acknowledged intent is retained for the lifetime of the bounded private snapshot; identifiers cannot be reused across tasks or after restore. Historical exact acknowledgment replay is idempotent; conflicting replay is rejected without mutation. Snapshots from unmerged .3 experiments lacking acknowledgment history are rejected if delivery state exists; do not reconstruct missing acknowledgments or silently migrate. No deployed .2 history format existed. The existing 8 MiB limit remains fail-closed; no automatic compaction or history deletion.
